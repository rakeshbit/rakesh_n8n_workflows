# AI Knowledge Base Chatbot using n8n, Pinecone, and OpenAIThis repository contains an advanced n8n workflow that demonstrates a dual-branch Retrieval-Augmented Generation (RAG) pipeline. The workflow handles both data ingestion (vector embedding data pipelines) and data retrieval (semantic search chat agent) within a unified low-code AI architecture.🚀 Workflow OverviewThe canvas consists of two decoupled operational streams:The Ingestion Pipeline (Left): Downloads corporate documentation from Google Drive, processes and chunks it via an OpenAI embedding data loader, and upserts the vectors into a Pinecone Index.The Retrieval & Chat Engine (Right): A conversational chat agent that intercepts user queries, queries the Pinecone vector index for relevant semantic context, and surfaces precise, grounded answers using an OpenAI LLM.🛠️ Architecture & Nodes Break Down1. Data Ingestion StreamManual Trigger (When clicking 'Execute workflow'): Initiates the manual data ingestion or sync cycle.Google Drive (Download file): Fetches target knowledge management documents, PDFs, or files from a specified folder path.Pinecone Vector Store (Pinecone Vector Store2): Acts as the vector database storage sink.Sub-Node Embeddings Default Data Loader OpenAI2: Implements document splitting/chunking logic and coordinates with OpenAI to generate dense text embedding vectors.2. Conversational RAG EngineChat Trigger (When chat message received): Implements a real-time conversational interface hook (compatible with n8n's native Chat UI).Chain Logic (Question and Answer Chain1): The primary LangChain-orchestrated QA framework mapping user queries against retrieved documents.Sub-Node OpenAI Chat Model: The conversational LLM (e.g., gpt-4o) generating human-like context-aware responses.Sub-Node Vector Store Retriever: Transforms the input query into a mathematical vector to perform top-K nearest neighbor lookups.Sub-Node Pinecone Vector Store1 & Embeddings OpenAI1: Connects to your reference Pinecone namespace using matching OpenAI text-embedding subroutines to extract matching context windows.📋 Prerequisites & Core DependenciesTo run this workflow effectively, you will require active accounts and API access tokens for the following platforms:IntegrationPurposeKey Requirementsn8n (v1.0+)Workflow OrchestrationAn active instance with Advanced AI features enabled.OpenAIEmbeddings & LLM GenerationAPI Key with token balance (text-embedding-3-small / gpt-4o).PineconeSemantic Vector StorageAn active Vector Index, API key, and Environment URL.Google WorkspaceDocument Data SourceOAuth2 Credentials with read permissions for Google Drive.🔧 Installation & Configuration StepsStep 1: Import the Workflow to n8nCopy the raw JSON configuration of this workflow (exported from your workspace).Open your n8n dashboard, click Workflows -> New Workflow.Use the keyboard shortcut Ctrl + V (or Cmd + V on Mac) to paste the nodes directly onto your empty canvas.Step 2: Set Up Service ConnectionsDouble-click each node containing a 🔴 warning indicator to configure credentials:Google Drive: Click Add Credential and authorize via OAuth2 or service account JSON.OpenAI Nodes: Add your OpenAI API Key. Note that both the Data Loader and the Retriever blocks must use identical OpenAI embedding models to avoid mathematical misalignment during queries.Pinecone Nodes: Input your API Key and specify your target environment index namespace.Step 3: Run Data IngestionPlace a text-dense reference file inside your targeted Google Drive directory.Click the Execute workflow button on the bottom menu to ingest your knowledge foundation. Verify that the executions finish with green success states.Step 4: Live TestingClick the Show Chat action drawer at the bottom of the n8n canvas interface. Type a niche question regarding your Google Drive document details to witness the agent dynamically retrieve context and answer your question.🛡️ Best Practices AppliedDecoupled Pipelines: Ingestion runs entirely out-of-band relative to the query response loop, ensuring high performance and eliminating chat execution bottlenecks.Token-Optimized Retrieval: Utilizing LangChain-based Vector Store Retrievers ensures only the most context-relevant text segments are processed by OpenAI, drastically reducing token consumption.📝 LicenseThis project is open-source and available under the MIT License.
